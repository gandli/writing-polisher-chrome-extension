# 项目需求设计

## 背景

用户在企业内网烟草专卖系统办理案件时，同事编写案件经过和相关材料，经常使用口语化表达，需要转换为标准专业的法律文书表达。由于内网无法访问互联网，需要一个完全离线的浏览器扩展来解决这个问题。

## 核心需求

1. **离线可用**：完全不依赖网络，所有数据内置，数据只存在本地
2. **口语转书面**：口语化表达 → 专业法律表达转换
3. **自动标记**：输入时自动识别口语化表达，高亮提示
4. **用户选择**：点击标记文本，弹窗显示建议，用户决定是否替换
5. **法条查询**：自动识别法条引用，点击查看完整条款内容
6. **可扩展性**：支持用户自定义添加词典和法条，支持导出导入团队共享

## 交互设计

### 文本标记

- 在可编辑区域（文本框、富文本编辑器）监听输入
- 使用词典匹配内容，给匹配到的口语化表达式添加黄色下划线背景
- 法条引用添加蓝色虚线背景标记

### 弹窗交互

- 用户点击被标记的文本，弹出气泡卡片
- 对于转换：显示原文和建议替换文本，提供「替换」和「忽略」按钮
- 对于法条：显示法条名称、条款号和完整内容，提供「关闭」按钮
- 点击弹窗外区域自动关闭弹窗

### 选项页（设置页面）

- **词典管理**
  - 列表展示所有词条（内置+自定义）
  - 支持新增词条
  - 支持删除自定义词条（内置词条不可删除）
  - 支持导出全部词条为 JSON
  - 支持从 JSON 文件导入词条

- **法条管理**
  - 类似词典管理，支持增删改查、导出导入

### 弹出窗口（Popup）

- 显示扩展功能说明
- 提供快速入口跳转到选项页
- 提供开启/关闭实时检测开关

## 数据设计

### 词典格式

```json
{
  "口语表达1": "专业表达1",
  "口语表达2": "专业表达2",
  "长句口语表达": "对应的长句专业表达"
}
```

### 法条格式

```json
{
  "法律名称": {
    "条款号": "条款内容",
    "条款号2": "条款内容2"
  },
  "烟草专卖法": {
    "31": "无烟草专卖批发企业许可证经营烟草制品批发业务的，由烟草专卖行政主管部门责令关闭或者停止经营烟草制品批发业务，没收违法所得，并处罚款。"
  }
}
```

### 存储设计

- 内置数据：打包进扩展，静态 JSON 文件
- 用户自定义数据：存储在 `chrome.storage.local`
- 合并逻辑：启动时合并内置 + 自定义，自定义覆盖内置

## 匹配算法设计

1. 将所有关键词按长度降序排序（长句优先匹配）
2. 扫描文本，查找所有匹配项
3. 标记匹配位置，避免重叠匹配
4. 在DOM中添加标记元素实现高亮

## 技术栈

- 框架：WXT + React + TypeScript
- 样式：Tailwind CSS
- 存储：chrome.storage.local
- 清单版本：MV3（Chrome 最新标准）
